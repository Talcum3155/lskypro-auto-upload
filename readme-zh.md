# Obsidian LskyPro Auto Upload Plugin

这是一个支持直接上传图片到图床[Lsky](https://github.com/lsky-org/lsky-pro)的工具，基于[renmu123/obsidian-image-auto-upload-plugin](https://github.com/renmu123/obsidian-image-auto-upload-plugin.git)改造。
**更新插件后记得重启一下 Obsidian**

## 本次更新内容

- 上传前压缩静态图片，可设置 WebP 质量、最长边和压缩起始大小。
- 当前笔记和全库上传使用同一批量处理流程，顺序上传并复用同批次的图片链接。
- 写回时定位原笔记，检查并保留上传期间的编辑；失败不会替换成无效链接。
- 源图片清理延迟到批量处理结束，检查引用后移入库内回收站。
- 网络超时、文件读取失败和接口错误均会提示；修改图床地址或 Token 后立即生效。

### 新命令使用方式

1. 打开命令面板（`Ctrl+P`）。
2. 输入并执行：`Upload all images - All notes in vault (reuse)`。
3. 插件会遍历所有 `.md` 文件，上传本地图片并替换引用，完成后会弹出统计提示。

说明：
- 本地图片会被上传；网络图片的处理遵循现有设置（`workOnNetWork` 与黑名单域名过滤）。
- 相对路径与绝对路径的解析与当前文件命令保持一致。

# 开始

1. 安装 LskyPro 图床，并进行配置，配置参考[官网](https://www.lsky.pro/)
2. 开启 LskyPro 的接口
3. 使用授权接口获取Token，并记录下来
4. 打开插件配置项，设置LskyPro域名(例如：https://lsky.xxx.com)
5. 设置LskyPro Token
6. 存储策略ID是可选配置，根据 LskyPro 的策略和自己的要求来配置，如果只有一个策略，可以不设置

# 特性

## 剪切板上传

支持黏贴剪切板的图片的时候直接上传，目前支持复制系统内图像直接上传。
支持通过设置 `frontmatter` 来控制单个文件的上传，默认值为 `true`，控制关闭请将该值设置为 `false`

支持 ".png", ".jpg", ".jpeg", ".bmp", ".gif", ".svg", ".tiff"（因为是直接调用LskyPro接口，理论上图床支持的文件都可以）

```yaml
---
image-auto-upload: true
---
```

## 批量上传一个文件中的所有图像文件

输入 `ctrl+P` 呼出面板，输入 `upload all images`(Upload all images-All images in the current file)，点击回车，就会自动开始上传。

现在也可以一次性处理所有笔记：

- 打开命令面板并执行：`Upload all images - All notes in vault (reuse)`
- 插件会复用同样的逻辑逐个处理并替换链接。

路径解析：

1. `./`、`../` 开头的路径，相对于当前笔记所在目录解析。
2. `/` 开头的路径，按库根目录解析。
3. 其他路径由 Obsidian 按当前笔记上下文解析，支持库内路径和最短链接。

## 批量下载网络图片到本地

输入 `ctrl+P` 呼出面板，输入 `download all images`，点击回车，就会自动开始下载。只在 win 进行过测试

## 支持右键菜单上传图片

目前已支持标准 md 以及 wiki 格式。支持相对路径以及绝对路径，需要进行正确设置，不然会引发奇怪的问题

## 支持拖拽上传

允许多文件拖拽

## 上传前压缩

默认对不小于 256 KB 的静态 PNG、JPEG、BMP 图片尝试转为 WebP，质量为 85%，保留原始分辨率和透明背景。粘贴、拖拽、当前笔记及全库上传共用此功能。请确保图床存储策略允许 WebP。

设置中可以关闭压缩，调整质量、起始大小以及最长边。最长边默认为 0（不缩放）；文字密集的长截图建议保持此设置。压缩为有损编码，85% 表示编码质量，不代表体积缩小 85%。仅在编码成功且体积变小时采用压缩结果，否则上传原图。GIF、APNG、已有 WebP、AVIF 和 SVG 不转换。

压缩本身不修改本地原图；原有“上传后删除源文件”开关仍独立生效。已上传的图床图片不会自动改变。

## 上传与文件保护

- 上传请求（含响应读取）有 60 秒超时；网络错误、无效响应、缺失文件会提示失败。失败笔记保留原引用，全库任务继续处理其他笔记，并统计成功、跳过和失败数量。
- 上传串行执行，避免同时解码大量图片；同一批次按本地路径、文件修改时间和大小复用上传结果。重复运行批量任务会被阻止。
- 写回时按原笔记定位，不受切换标签页影响。批量上传或下载期间修改了笔记时，取消该篇写回并提示重试。粘贴和拖拽使用原位置的占位符，保留等待期间输入的文字。
- 全库批量上传也尊重 `image-auto-upload: false`。本地相对路径通过当前笔记解析；代码块中的图片示例不会上传。
- 图床域名和 Token 修改后立即对后续请求生效，Token 可包含 `Bearer` 前缀。
- 启用“上传后删除源文件”时，在整批任务结束后检查 Markdown、Canvas 和打开编辑器中的引用；仍被引用、尚未保存替换结果或被修改的图片会保留。符合条件的图片移入库内 `.trash`，不直接永久删除。模糊引用和未更新的链接缓存也会使原图保留。
- 上传成功但笔记发生编辑冲突时，已上传的图床图片不会自动回滚删除。

开发验证：`npm test` 运行回归测试，`npm run build` 生成 `main.js`。当前安装的 Obsidian 类型声明存在上游类型错误，可用 `npx tsc --noEmit --skipLibCheck` 检查项目代码。
